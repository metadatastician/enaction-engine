= Proof Status — Enaction Engine
:toc:

== Classification rule

This ledger distinguishes four things that must not be conflated:

Confirmed proof:: A product-connected proposition was checked by its proof
tool against the actual source of authority.
Compiled scaffold:: A proof-assistant file compiles, but explicitly describes
itself as a template or does not connect to Enaction's implementation.
Tested correspondence:: Executable implementations agree on observed cases;
this is evidence, but not a formal proof.
Gap:: The proposition, implementation connection, toolchain or fail-closed gate
needed for a proof claim is absent or failing.

Scaffolding is never reported as proof. A passing aggregate proof runner means
its gated modules compiled and its quarantined modules failed as recorded; it
does not mean every file is a completed Enaction proof.

== Confirmed product proofs

The ABI claims below were rechecked on 2026-08-29 with Idris2 0.7.0 by running
`idris2 --typecheck abi.ipkg`. The Rust claim was checked with Creusot 0.13.0,
Why3 1.8.2+git and its pinned `nightly-2026-06-22` toolchain.

[cols="1,3,3", options="header"]
|===
| ID | Confirmed proposition | Source

| ABI-P1
| Request fields are aligned under the declared 56-byte, 8-aligned layout.
| `src/interface/Abi/Accelerator.idr` — `requestLayoutValid`

| ABI-P2
| The 16-byte pointer/length buffer layout satisfies the declared alignment.
| `src/interface/Abi/Accelerator.idr` — `bufferLayoutValid`

| ABI-P3
| The declared 32-byte capability layout satisfies its field alignments.
| `src/interface/Abi/Accelerator.idr` — `capabilityLayoutValid`

| ABI-P4
| The declared 24-byte evidence layout satisfies its field alignments.
| `src/interface/Abi/Accelerator.idr` — `evidenceLayoutValid`

| ABI-P5
| The current version is accepted; a wrong major and newer minor are rejected.
| `acceptsCurrentVersion`, `rejectsWrongMajor`, `rejectsNewerMinor`

| ABI-P6
| The operation-code function is injective over all seven admitted operations;
  consequently every pair of different operations has different codes.
| `operationCodeInjective` covers all 49 ordered constructor pairs, and
  `differentOperationsHaveDifferentCodes` exposes the contrapositive form.
  The five earlier named pair proofs remain as compatibility witnesses derived
  from the exhaustive theorem.

| RUST-P1
| The production accelerator version predicate returns true exactly when host
  and request majors match and the requested minor is no newer than the host.
| `crates/enaction-accelerator/src/version.rs` — `ContractVersion::accepts`;
  `scripts/check-creusot.sh` proved all four generated files through the narrow
  harness in `verification/creusot`.
|===

ABI-P6 is exhaustive: all seven equal-constructor cases and all 42 directed
unequal-constructor cases are checked by Idris2. Equivalently, this covers all
21 unordered pairs of different operations.

RUST-P1 is connected to production source rather than a copied model: the
verification harness includes the exact module compiled by
`enaction-accelerator`. A negative control changed `<=` to `<`; Creusot then
failed `Coma.vc_accepts` with only 3/4 files proved. Restoring the implementation
returned the gate to 4/4. This does not prove any other Rust module.

== Tested implementation correspondence

These checks passed on 2026-08-29, but remain tests rather than proofs:

* `scripts/generate-accelerator-abi.sh --check` reproduced the committed C,
  Zig, Rust and Julia declarations, symbol inventory and source digest.
* `zig build test` passed for the pure-Zig FFI.
* `just e2e` passed 3/3 gates with zero skips: corpus integrity, scalar Rust
  reference conformance, and Rust/Zig byte-for-byte parity across fresh
  processes.
* GitHub's exact pull-request head passed workspace Rust tests, Clippy,
  formatting and the separately built Zig-linked native adapter.

These observations support the model-to-code correspondence. They do not prove
the Rust implementation or the C/Zig/Rust/Julia toolchain end to end.

== Compiled scaffolding and disconnected proofs

The canonical `just proof-check-all` sweep passed on 2026-08-29 and accounted
for every file in its manifests. Its product meaning is limited:

* `verification/proofs/idris2/ABI/Foreign.idr` compiles, but proves properties
  of a generic `FFIResult`; it is not connected to the production accelerator
  exports.
* `verification/proofs/agda/Properties.agda` compiles under `agda --safe`, but
  labels itself an Agda proof template and proves generic list/monotonicity
  examples.
* `verification/proofs/coq/TypeSafety.v` compiles, but labels itself a Coq proof
  template and proves soundness of an example expression language unrelated to
  Enaction.
* `src/interface/Abi/Foreign.idr`, `Types.idr`, and the generic Zig integration
  test still contain RSR-template names or explicit template language. Their
  presence in a typechecked package does not establish the advertised generic
  FFI safety claim.

== Explicit gaps

[cols="1,3,3", options="header"]
|===
| ID | Gap | Evidence required to close it

| ABI-G1
| Non-null pointer proof in the generic proof tree is quarantined.
| Repair `verification/proofs/idris2/ABI/Pointers.idr`, connect it to the
  production ABI, and promote it to `gated`.

| ABI-G2
| Generic memory-layout and platform-size modules are quarantined.
| Repair `ABI/Layout.idr` and `ABI/Platform.idr`, then state which production
  declarations each proposition governs.

| ABI-G3
| Generic C-ABI compliance is quarantined and depends on ABI-G2.
| Repair `ABI/Compliance.idr`, connect it to generated declarations, and gate
  the connection.

| TP-G1
| Generic Idris2 core types and Lean public-API safety are quarantined.
| Repair, product-specialise, and promote them from quarantine.

| RUST-G1
| Creusot proves only the production version-compatibility predicate; planner,
  integer kernels, floating-point kernels and native adapter remain unproved.
| Admit each exact production module to the narrow harness only when Creusot
  can translate its dependencies, then state and positively control its own
  contract. Creusot 0.13 currently ICEs on the planner's trait-object surface.

| RUST-G2
| The fail-closed local Creusot gate is not yet provisioned in GitHub Actions.
| Install the exact Creusot 0.13.0 release and pinned Rust toolchain in a
  required workflow; do not call local tool installation a CI gate.

| CHAIN-G1
| Model-to-generated-code-to-Zig-to-Rust equivalence is tested, not proved.
| Add a proof-carrying or mechanically checked refinement chain; keep the
  current cross-language tests as independent evidence.

| HEX-G1
| The FFI passes the Hexadeca purity floor but has no sixteen-connector unified
  protocol surface.
| Admit such an adapter only for a real protocol consumer; do not treat an
  internal numeric ABI as a protocol connector by naming alone.
|===
