== Estate interface constraints

SNIF:: A future BEAM numeric/buffer adapter uses the current SNIF boundary:
freestanding Wasm, Zig `ReleaseSafe`, explicit error results, bounded execution,
and no silent backend fallback. Wider `erl_nif` facilities require a separate
ADR.

Zig Hexadeca:: Enaction's FFI contains no `std.fs` or `std.io`, satisfying the
current purity gate. It does not implement the sixteen-connector unified API
and must not claim that surface without a real protocol-facing consumer.

Idris2 ABI and Zig FFI:: Idris2 is normative for ABI types/layouts; generated
declarations are deterministic wire artifacts; Zig implements the boundary;
host languages do not independently redefine it.

Rust and Creusot:: Two production predicates now have exact Creusot contracts
and fail-closed, positive-controlled local checks. No proof claim extends to
package-validation callers, the planner, kernels or adapter; GitHub Actions
provisioning remains a gap.

Idris2 pointer policy:: The production ABI now proves that a valid non-empty
buffer requires data and a valid null data pointer denotes an empty buffer.
Zig exercises the corresponding rejection paths, but the Idris-to-Zig
refinement remains a recorded gap rather than a proof claim.

Idris2 layout bounds:: The production `CABICompliant` certificate now requires
every field to be aligned and to end within its declared struct size. All 33
fields across request, buffer, capability and evidence are covered. Target
compiler representation remains correspondence evidence, not a proved
refinement.

Native target boundary:: Accelerator ABI v1 is now explicitly limited to
64-bit-pointer targets by a production Zig compile-time guard. Buffer sizes and
field offsets are checked against the Idris-declared layout. A wasm32 negative
control reaches the guard and fails. No claim is made that the generic Idris
platform template detects the build target, or that each documented
OS/architecture tuple has a proved compiler-layout refinement.
