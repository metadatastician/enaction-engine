== Evidence required before grading

A future assessment must first define the independently gradable component
boundaries and pin the applicable CRG version. For every component it must
record, rather than assume:

* the applicable RSR and estate requirements and their verification results;
* build, test, lint, and security evidence, including toolchain versions and
  supported targets;
* source orientation, API boundaries, known limitations, and integration
  evidence; and
* the specific unmet criteria for the next grade, with links to durable logs,
  workflow runs, tests, or decisions.

Evidence must be collected from actual runs. The repository's presence of a
workflow or a task recipe is not evidence that the gate passed. Component
grades must be justified individually; an aggregate grade may be published
only after a formal assessment establishes the aggregation rule and supports
it with evidence.

== Current integration and assurance limits

* No game or executable host currently consumes the workspace as a whole.
* The Zig-linked native adapter requires its separately pinned Zig toolchain;
  ordinary default-member Rust commands do not build it.
* Formal proof sources require their language-specific provers. A missing
  prover is a blocked gate, not a successful proof result.
* There is no documented period of in-context dogfooding or external consumer
  feedback for these engine components.
* No SOC 3 report, ISO/IEC 27001 certification, CIAQ assessment, or CRG grade
  is claimed by this project.

These are statements of current scope and missing evidence, not inferred CRG
grades. Revisit this page only when a real assessment has been performed.
