= Accelerator ABI and FFI Boundary
:toc:

== Scope

The foreign-function interface in this repository is a narrow CPU accelerator
boundary. It is not a general engine API, game-host SDK, application lifecycle
API, or UMS integration.

== Authority and implementation

[cols="1,3"]
|===
| Layer | Responsibility

| Idris2 authority
| `src/interface/Abi/Accelerator.idr` defines the versioned ABI types,
  discriminants and declared layouts. `Layout.idr` supplies the layout model.

| Generated declarations
| `Abi.Generate` renders C-compatible, Zig, Rust and Julia declarations into
  `src/interface/generated/abi/`. These files are outputs, not independent
  authorities.

| Zig implementation
| `src/interface/ffi/src/accelerator.zig` implements the exported operations;
  `axiom_matmul.zig` and `axiom_pointwise.zig` contain the current CPU kernels.

| Rust adapter
| `crates/enaction-accelerator-native/` owns the Rust-side adapter and links
  the Zig-built library. The ordinary Rust job does not silently include it;
  `.github/workflows/rust-ci.yml` has a separate Zig-enabled CI job.
|===

The ABI is version 1 and currently limited to targets with 64-bit pointers.
The implementation rejects unsupported pointer widths. Passing a build or
layout check is empirical correspondence evidence; it is not a theorem that
every target compiler implements the Idris layout model.

== Generate and verify declarations

[source,sh]
----
idris2 --typecheck abi.ipkg
scripts/generate-accelerator-abi.sh
scripts/generate-accelerator-abi.sh --check
----

Idris2 0.7.0 does not provide a `c-header` code generator. `Abi.Generate` is
the checked deterministic renderer. Do not reintroduce an `idris2 --cg
c-header` path or hand-maintained duplicate ABI declarations.

== Build and run the Zig tests

[source,sh]
----
cd src/interface/ffi
zig build
zig build test
----

The inline Zig tests cover implemented operations, validation failures,
non-finite inputs, overflow, alias rejection and output atomicity. They do not
show that a game host, UMS preview, GPU backend or every documented OS/target
combination is integrated.

== Build the Rust adapter

[source,sh]
----
cargo check --locked -p enaction-accelerator-native --all-targets
cargo clippy --locked -p enaction-accelerator-native --all-targets -- -D warnings
cargo test --locked -p enaction-accelerator-native --all-targets
----

These commands require Rust stable and the pinned Zig release used by the
repository's accelerator CI job. The adapter does not establish a stable
external ABI commitment beyond the checked versioned contract.

== Evidence boundary

`docs/status/PROOF-STATUS.adoc` distinguishes the propositions checked by
Idris2 and Creusot from generated-code checks, Zig/Rust tests, compile-time
guards and target-specific observations. In particular, passing the current
conformance tests is tested correspondence, not a proof of all Zig behavior or
an end-to-end compiler refinement.

The repository currently has no generic `enaction_engine_init` / `process`
lifecycle API, no placeholder integration test, and no consumer-ready engine
SDK. Future bindings must begin with a real consumer and an accepted interface
contract; do not add an empty FFI facade.
