= Enaction Engine: Claim-to-Evidence Map
:toc:
:icons: font

This document maps the principal claims in `README.adoc` to evidence. A passing
test demonstrates only the property it observes; it does not turn the current
timing crate into a complete game engine.

== Deterministic whole-step simulation support

Claim:: A host can advance simulation in whole, equal steps without handing
partial frame time to its simulation callback.
Implementation artifact:: `crates/enaction-time/src/step.rs`:
`FixedStep::advance`, `alpha`, `took_shortcut`, and `reset`.
Verification gate:: `crates/enaction-time/tests/step.rs`, crate doctests,
`cargo test --workspace`.
Demonstrated:: Accumulation, whole-step accounting, remainder preservation,
hostile-input handling, reset behaviour, and capped catch-up.
Not demonstrated:: Whole-game determinism, deterministic host code, replay, or
network lockstep.
Real-game status:: `FixedStep` has not run in a real game.
Provenance:: New engine code informed by accumulator practice, not extracted
IDApTIK code.

== Interpolation is render-only

Claim:: `DoubleBuffer` samples two already-simulated states and is designed for
rendering only.
Implementation artifact:: `crates/enaction-time/src/blend.rs`; crate-level
documentation in `src/lib.rs`.
Verification gate:: `crates/enaction-time/tests/blend.rs` and doctests.
Demonstrated:: Sampling does not mutate the buffer and exact endpoints expose
the two committed states.
Not demonstrated:: Rust's type system cannot prove that a host never writes a
sampled value back into simulation. That remains an integration invariant.
Real-game status:: The interpolation design has served in IDApTIK.
Provenance:: Generalised from IDApTIK experience and its interpolation core.

== Continuous versus discrete values

Claim:: Continuous quantities may blend; discrete values must be read from the
current completed step.
Implementation artifact:: `Blend`, `DoubleBuffer::sample`, and
`DoubleBuffer::curr` in `crates/enaction-time/src/blend.rs`.
Verification gate:: Endpoint, monotonicity, slot, and current-state tests in
`crates/enaction-time/tests/blend.rs`.
Demonstrated:: Numeric continuous values blend and raw current values remain
available.
Not demonstrated:: The crate cannot infer whether a host's numeric field is
semantically continuous. Facing direction, visibility, enums, and booleans
remain host responsibilities.
Real-game status:: The rule comes from IDApTIK rendering experience.
Provenance:: Derived from IDApTIK bugs and tests.

== Discontinuity handling

Claim:: A teleport, restart, load, or resynchronisation uses `commit` then
`snap`, not `snap` alone.
Implementation artifact:: `DoubleBuffer::commit` and `DoubleBuffer::snap`.
Verification gate:: `commit_then_snap_leaves_nothing_to_interpolate` and
`snap_alone_would_lose_the_fresh_state`.
Demonstrated:: The fresh value becomes both previous and current, preventing a
rendered slide across the discontinuity.
Not demonstrated:: Automatic discovery of discontinuities or coordination with
physics, networking, or persistence.
Real-game status:: The failure mode was observed through IDApTIK experience.
Provenance:: Derived from IDApTIK.

== Allocation claim

Claim:: The current buffer representation and timing/interpolation operations
contain no heap-owning storage or explicit allocation.
Implementation artifact:: `DoubleBuffer<T, N>` contains exactly two `[T; N]`
arrays; `FixedStep` contains scalar fields.
Verification gate:: `the_buffer_is_inline_fixed_size_storage`, source review,
Clippy, and the Rust type layouts.
Demonstrated:: The buffer's measured size equals two inline arrays for tested
types, and the implementation contains no `Vec`, `Box`, or allocator call.
Not demonstrated:: A whole-process allocation trace, allocations inside a
host's `Blend` implementation, or allocation behaviour of future subsystems.
Real-game status:: The buffer shape derives from IDApTIK; the crate itself has
not replaced the game implementation.
Provenance:: Extracted design with repository-local verification.

== IDApTIK provenance

Claim:: IDApTIK is the first proving ground.
Implementation artifact:: Its independent Rust core at
`metadatastician/IDApTIK`, plus provenance comments and ADR-0005 here.
Verification gate:: Repository-local tests reproduce the relevant behavioural
cases; comparison with IDApTIK is a review activity, not an automated cross-repo
gate.
Demonstrated:: The buffer and interpolation rules are based on actual game
experience.
Not demonstrated:: That `enaction-time` is already integrated into IDApTIK, or
that every engine facility is extracted from it.
Real-game status:: The source experience is real; the extracted crate is not
yet the game's dependency.
Provenance:: Mixed: interpolation is derived from IDApTIK; `FixedStep` is new.

== Complete engine subsystems are absent

Claim:: The repository is currently only the first deterministic substrate.
Implementation artifact:: The workspace lists only `crates/enaction-time`.
Verification gate:: `cargo metadata`, workspace tests, repository-tree review,
and the speculative-subsystem rule in ADR-0012.
Demonstrated:: No renderer, ECS, audio, input, assets, networking, general AI,
physics, or complete cognitive/affective/conative crate is shipped here.
Not demonstrated:: Any of those future capabilities.
Real-game status:: Not applicable.
Provenance:: Honest current repository state.

== Future UMS contract

Claim:: UMS may author and validate content through versioned contracts without
becoming a runtime dependency.
Implementation artifact:: `docs/architecture/UMS-INTEGRATION.adoc` and ADR-0009.
Verification gate:: Architecture review only; there is no adapter or contract
implementation yet.
Demonstrated:: The intended dependency boundary and prohibition on cycles.
Not demonstrated:: Schema stability, package compatibility, preview parity, or
an actual UMS adapter.
Real-game status:: No.
Provenance:: Design direction, not extracted code.

== Rust now, AffineScript later

Claim:: Rust is current; AffineScript adoption is gated on release and
typed-Wasm readiness.
Implementation artifact:: `Cargo.toml`, `crates/enaction-time`, and ADR-0004.
Verification gate:: Cargo formatting, tests, and Clippy. No AffineScript gate is
present because no AffineScript implementation is claimed.
Demonstrated:: The current Rust implementation builds and is tested.
Not demonstrated:: A viable port, language parity, a stable compiler release,
or typed-Wasm integration.
Real-game status:: The IDApTIK experience is Rust; no engine AffineScript code
has served in a game.
Provenance:: Current implementation plus an explicitly conditional direction.

== Complete-engine direction

Claim:: Enaction Engine is scoped as a complete game engine in the long term.
Implementation artifact:: `ARCHITECTURE.md`, `docs/status/ROADMAP.adoc`, and
ADRs 0007, 0010, and 0012.
Verification gate:: None for unimplemented direction; each future component
must introduce its own implementation evidence and tests before documentation
may move it into “implemented now.”
Demonstrated:: A modular destination and admission rule.
Not demonstrated:: Rendering, physics, audio, input, assets, networking,
persistence, tools, or full cognition/affect/conation.
Real-game status:: Only the timing/interpolation provenance described above.
Provenance:: Incremental extraction strategy, with Chronicles of Slavia planned
as the second abstraction test.
