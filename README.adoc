A runtime for deterministic simulations: fixed-timestep stepping, and render
interpolation that smooths the result onto a display running at any rate.

== The constraint everything follows from

The simulation advances in **whole, equal steps**, and nothing the renderer does
may change that.

Variable `dt` makes a run depend on frame timing, and a run that depends on frame
timing cannot be replayed, snapshotted, or lockstepped across a network. So the
engine steps the simulation on a fixed clock and hands the renderer a *fraction*
to draw with — never a partial step to simulate.

== Status: early, and honest about it

This is the timing and interpolation core. It is **not yet a general-purpose game
engine**: there is no renderer, no ECS, no asset pipeline, no audio and no input
handling.

What exists is a timing crate plus one deliberately small typed event seam:

[cols="1,3,1"]
|===
|Component |What it does |Provenance

|`DoubleBuffer<T, N>`
|Holds the last two simulated states and samples between them. Two inline
fixed-size arrays; nothing allocates.
|Proven in IDApTIK

|`FixedStep`
|Turns real elapsed time into whole owed steps plus a fraction, with a
spiral-of-death guard.
|New here — never run a real game

|`enaction-cognition`
|Separates mechanical, epistemic, affective, conative, behavioural-selection
and social/relational trace events while leaving vocabulary to the game.
|New here — not yet linked by either game
|===

That last column is the point. This engine is being **extracted from a working
game**, not designed in the abstract: the proving ground is
link:https://github.com/metadatastician/IDApTIK[IDApTIK], whose Rust core already
holds a deterministic, event-sourced simulation with replay and snapshot tests.
A component earns its way in by working somewhere real first, and where one has
not, the docs say so.

== Using it

[source,rust]
----
use affective_time::{DoubleBuffer, FixedStep};

let mut clock = FixedStep::from_hz(60.0);
let mut buffer: DoubleBuffer<f64, 1> = DoubleBuffer::new();
buffer.prime(&[world.x()]);

// once per frame
for _ in 0..clock.advance(real_dt) {
    world.step();                    // whole steps only
    buffer.commit(&[world.x()]);
}
draw(buffer.sample(0, clock.alpha()));
----

The engine deliberately knows nothing about what a slot means — the host keeps
its own indices. That boundary is what lets the same buffers serve a 2D
platformer, a network simulation and a terminal frontend.

=== Three rules worth knowing before you integrate

. **Interpolation is render-only.** No sampled value may flow back into
  simulation state. Determinism rests on this.
. **Only continuous quantities blend.** Booleans, enums and visibility are read
  live. So is a *facing direction* — lerping a sign through zero draws the
  subject facing neither way.
. **A discontinuity is `commit` then `snap`, never `snap` alone.** On a restart
  or teleport the fresh state still has to enter the buffer; `snap` only
  discards the stale previous step.

All three came from bugs found by testing in IDApTIK, and all three are pinned
by tests here. See link:docs/decisions/0005-fixed-timestep-and-interpolation.adoc[ADR-0005].

== Current integration evidence

`crates/affective-time/tests/idaptik_parity.rs` covers healthy fixed-step
accounting, hostile elapsed time, interpolation, discrete versus continuous
state, discontinuities and snapshot/restart interaction. It proves the
extracted interpolation boundary; it does not prove that IDApTIK uses
`FixedStep`. IDApTIK still uses Bevy's accumulator, and this pass deliberately
does not replace it.

Enaction is a runtime dependency candidate below games. It does not depend on
UMS. An optional UMS preview adapter may be added later, but released games must
not depend on the UMS UI. The current IDApTIK appraisal example is game-local;
the general `enaction-cognition` seam is new and remains unadopted.

== Language

The intended long-term implementation language is **AffineScript**. This is
Rust, deliberately and for now: AffineScript is a real working compiler, but it
ships no release artefact and its typed-wasm bridge is still gated. The port is
gated on both of those, and would pin to a compiler commit rather than a version.
See link:docs/decisions/0004-rust-now-affinescript-later.adoc[ADR-0004].
